The loop (ARCHITECTURE.md has the action list): the work list is every cell on a failing sum after the first read, then every disagreement with the published file. For each item the model (`claude-haiku`) sees the item, what has been tried and the checks' output, and answers with one JSON action. Code carries the action out, enforces the rules and writes an event. Re-read targets: a block half, a column slice, or a single cell, at 300 or 400 dpi. Each action is a neatlogs TOOL span tagged with run, county, page, block and cell; the loop is an AGENT span.

The audit (ARCHITECTURE.md, "The audit"): map EARLY to `early_voting`, ABSENTEE to `absentee`, PRECINCT to `election_day`, the small total to `votes`. Match contests and candidates by normalised labels first; send only what is left to the model once, and check its mapping in code (one-to-one, county totals close). Classify each disagreement as `file_row_fails_own_total`, `wrong_number`, `wrong_column`, `wrong_precinct`, `missing_row` or `extra_row`. Settle it with the printed totals. Every finding has: county, office, candidate, precinct, part, file value, scan value, kind, status (`settled_against_file`, `cannot_verify` or `document_inconsistent`), the sums that decide it (terms, printed total, which side matches), the crop path, and `confirmed_by_person: false`.
Policy (`policy.py`): one question, id `document_disagrees_with_itself`; the default answer is "follow the cells as printed and list the printed total as inconsistent", stored in `policy.json` with `answered_by: "default, not yet confirmed by a person"`.
