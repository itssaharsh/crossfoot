What the other seven scans look like (first pages checked by eye on 11 October 2026; look at the pages yourself before writing prompts):
- Cottle, Jones, Lynn, San Saba, Scurry: an Electionware report, portrait, one precinct per section (a heading such as "PRECINCT 101" or "Precinct 1"). A Statistics block (registered voters, ballots cast), then one block per contest. Each candidate is a row with four numbers under the headings TOTAL, Absentee, Early Voting, Election Day. Jones and Lynn also print "Total Votes Cast", "Overvotes" and "Undervotes" rows per contest; Cottle, San Saba and Scurry print write-in totals.
- Foard: a different vendor's "Precinct Report", landscape. Columns are Absentee, Early, Election, Total, each a count followed by a percentage, with "Cast Votes", "Over Votes" and "Under Votes" rows per contest. Ignore the percentages.
- Limestone: a plain-text report in two columns that prints only VOTES and PERCENT per candidate. It has no breakdown and no printed contest totals, and its published file has no parts either. Nothing on it can be cross-checked.

Acceptance (REQUIRED):
- WHEN a county is started THE SYSTEM SHALL decide its layout from its first page (`layouts/profile.py`): `matrix`, `report` with the column order it found, or `no_printed_totals`; then read the first page under that decision and reject it if more than a third of the sums fail
- WHEN the layout is `no_printed_totals` (Limestone) THE SYSTEM SHALL not read the county, and report it as "nothing on this scan can be cross-checked; left as published"
- WHEN a report-layout county is read THE SYSTEM SHALL check every row (total = absentee + early voting + election day) and, where the page prints one, every contest total (the candidates' totals add to "Total Votes Cast" or "Cast Votes")
- WHEN `crossfoot audit --county san_saba` finishes THE SYSTEM SHALL list the published row that fails its own total (precinct 2A, a presidential row) with the scan's four numbers for that row and a crop
- AC-4: WHEN `crossfoot audit --all` is stopped and run again with `--resume <run_id>` THE SYSTEM SHALL skip closed counties and accepted cells
- IF the metered cost would pass `--budget` THEN THE SYSTEM SHALL stop before the next call, write what it has, and list the counties not reached
- IF one county fails (download, layout, model errors) THEN THE SYSTEM SHALL record why and go on to the next
