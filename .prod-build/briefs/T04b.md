Acceptance (REQUIRED):
- WHEN `crossfoot audit --all` runs THE SYSTEM SHALL take the counties in a fixed order (panola, san_saba, cottle, jones, lynn, scurry, foard, limestone), print one line per county as it starts and ends, and never ask for input
- AC-4: WHEN it is stopped and run again with `--resume <run_id>` THE SYSTEM SHALL skip closed counties and accepted cells (tested with a fake model: no second call for an accepted cell)
- IF the metered cost would pass `--budget` THEN THE SYSTEM SHALL stop before the next call, write what it has, and list the counties not reached (tested)
- IF one county fails (download, layout not decided, model errors) THEN THE SYSTEM SHALL record why in the summary and go on to the next (tested)
- Reads may overlap: up to three model calls in flight, with call starts still at least 1.1 seconds apart (the gateway allows 60 a minute). The ledger is written from one thread.
- `summary.json`: per county: layout, pages, cells read, sums passing and failing after the first read, cells re-read, cells accepted, cannot_verify, findings by kind and by status, model calls by model, tokens, metered cost, seconds; and totals. `summary.md` says the same in a table, plus the counties that were skipped and why. Only numbers the run recorded.
- Each county's run is one neatlogs trace (a WORKFLOW span named for the county) so a county can be found by name; the run id is an attribute on every span.
